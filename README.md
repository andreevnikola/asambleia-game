# Дистриктна Интеракт Асамблея - „Игра“

Платформа за разпределение на отборите и управление на презентациите по време на „Игра“ на Дистриктната Интеракт Асамблея.

- **Участниците** (`/`) въвеждат първо име, получават 3-цифрен код и отбор, виждат въпросите и получават известие на телефона, когато са избрани за лидери на отбора.
- **Администраторът** (`/admin`) подготвя отбори и въпроси, стартира играта, определя лидерите с анимация за проектор и води презентациите (3 минути на въпрос).

Next.js 16 (App Router) · Tailwind CSS 4 · Neon Postgres · Playwright · хостинг във Vercel.

## Как работи (накратко)

- Цялото състояние е в Postgres. Нищо не е в паметта на сървъра, затова обновяване на страница, нов Vercel инстанс или изгубена връзка не губят нищо.
- Телефоните получават промените по **SSE** (`/api/stream`). Потокът праща пълен „снимков“ изглед при свързване и при всяка промяна, затова при прекъсване и ново свързване нищо не се губи. Вместо брокер за съобщения всеки поток проверява по един малък ред в Neon на всеки 2 секунди. Потокът сам приключва след 50 секунди и браузърът се свързва отново веднага. Като резервен вариант страницата на участника пита сървъра на всеки 12 секунди.
- Лидерите се определят предварително, но участникът вижда избора си едва когато името му се покаже на екрана на администратора (екранът на администратора вика `/api/admin/reveal` при всяко разкриване).
- Записването на участник е една атомарна SQL заявка: уникален код (100–999) и отбор по кръгова схема, дори при 100 едновременни влизания.
- След края на играта (или при „Нулирай играта“) **всички данни за участниците се изтриват**. Отборите, въпросите и времената остават.

## Настройка

```bash
pnpm install
cp .env.example .env      # попълнете DATABASE_URL, DATABASE_URL_POOLED, ADMIN_SECRET
pnpm db:migrate           # създава таблиците в Neon (безопасно да се пуска многократно)
pnpm dev                  # http://localhost:3000   (админ: /admin)
```

| Променлива | За какво е |
| --- | --- |
| `DATABASE_URL` | Директна (unpooled) връзка към Neon. Използва се само от `pnpm db:migrate`. |
| `DATABASE_URL_POOLED` | Pooled връзка (хостът съдържа `-pooler`). Използва се от приложението. Ако липсва, се ползва `DATABASE_URL`. |
| `ADMIN_SECRET` | Тайният ключ за `/admin`. Пази се в `localStorage` на браузъра до „Изход“. |
| `SSE_POLL_MS`, `SSE_MAX_MS` | По желание: интервал на проверка (2000) и живот на един SSE поток (50000). |

`.env` е в `.gitignore`. Никога не го качвайте в GitHub.

## Тестове

```bash
pnpm test           # всичко: логика, API/натоварване, браузърни E2E и симулация
pnpm test:load      # само API/натоварване (100 едновременни влизания, 100 SSE потока, състезания)
pnpm typecheck
```

Тестовете стартират production build (`next build && next start`) на порт 3200 с кратки времена и тестов ключ.

**Тестовете работят върху базата от `.env`, но не я губят:** преди старта се записват отборите, въпросите и времената в `.e2e-snapshot.json`. След края (или при следващ старт, ако тестът е прекъснат) те се възстановяват. Тестовете **отказват да стартират**, ако в момента тече игра с участници (заобикаля се с `E2E_FORCE=1`, не го ползвайте в деня на събитието).

За да проверите SSE на истинската инфраструктура на Vercel:

```bash
BASE_URL=https://<вашият-домейн> E2E_ADMIN_SECRET=<ADMIN_SECRET> pnpm test:load
```

Локалният `.env` и Vercel трябва да сочат към една и съща база: тестовете подготвят и възстановяват данните директно в нея.

## Деплой във Vercel

1. *Add New → Project* → изберете репото `andreevnikola/asambleia-game`.
2. В *Environment Variables* добавете `DATABASE_URL`, `DATABASE_URL_POOLED` и `ADMIN_SECRET`.
3. `vercel.json` вече задава регион `fra1`. Той съвпада с Neon `eu-central-1` (Франкфурт), така че заявките към базата са бързи.
4. За събитието използвайте **production домейна**. Preview адресите може да са защитени с Vercel Authentication и участниците няма да имат достъп.
5. Пуснете `pnpm db:migrate` локално веднъж срещу същата база.

## В деня на събитието

1. Около 30 минути преди началото: `/admin` → *Старт със симулация* → пуснете „Определи лидери“ до края → *Нулирай играта*. Това събужда Neon и проверява целия път.
2. Въведете отбори, въпроси и (ако трябва) времената в *Подготовка*. Времената се променят само там.
3. Изискване: **отборите ≥ въпросите**. Всеки въпрос получава поне един говорител.
4. *Започни играта* и покажете адреса на участниците (QR код към `/`).
5. Когато участниците са влезли: *Определи лидери*. Екранът минава в режим за проектор.
6. След резултатите: *Започни презентацията на В1* → при „Времето изтече“ → *Продължи*. Последният въпрос завършва играта и изтрива данните на участниците.
7. Ако нещо се обърка: *Нулирай играта* (изтрива участниците, запазва настройките).

На екраните за проектор (избор на лидери, резултати, презентация):

- **Пропускане на изчакването.** Между два въпроса при избора на лидери има кръгче с отброяване. Когато мишката е върху него, числото се превръща в бутон за пропускане и играта веднага продължава.
- **Пропускане на времето за говорене.** Бледата иконка до големия таймер пита за потвърждение и минава към следващия въпрос с нов, пълен таймер (при последния въпрос играта приключва и данните на участниците се изтриват). Часовникът на сървъра не се променя: това е същата стъпка като *Продължи* след „Времето изтече“.
- **Спри презентацията** (горе вдясно, до „Изход“) връща към таблото на играта. Избраните лидери се отменят и можеш да ги определиш наново, а участниците, отборите и въпросите остават. Телефоните губят известието за лидер.

## Структура

```
app/                страници (/, /admin) и API (app/api/**)
components/         player/, admin/, ui/
lib/                game.ts (цялата работа с базата и преходите между етапите), logic.ts (чиста логика)
db/schema.sql       схемата (прилага се от scripts/migrate.mjs)
tests/              logic, api (натоварване), e2e (браузър), simulation
```
